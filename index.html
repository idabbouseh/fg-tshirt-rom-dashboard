How to combine T-shirt ROMs

1 Start with the module

For a net-new implementation, pick the T-shirt for each module in scope — Contingent, SOW, or Profile Worker (or the ERP Editions). Multiple modules? Add the estimates together. Any reduction in timeline/effort for economies of scale can be determined during actual planning. Deck slide 1, 12-Aug-2026

2 Add integrations

If SAP-led integration services are in scope, add the specific integration T-shirts (Ariba B&I, SuccessFactors) on top of the base module T-shirt.

3 Add regions

Base T-shirts assume one region. Additional simultaneous regions add Country Expansion T-shirts. Country Expansion, Integration and MSP Transfer T-shirts also work standalone for existing customers.

! Delivery model note — partner-led ≠ Fieldglass-free

Even where integration configuration is partner or client self-service (Small tier), specific activities remain SAP Fieldglass-performed regardless of delivery model: tenant endpoint configuration, Company Configuration changes, extrinsic/custom field enablement on integration payloads, and the integration mapping specification. Set this expectation early in the sales cycle. Added 2026

Integration T-Shirts

SAP-led integration packages layered on a base module T-shirt, or sold standalone to existing customers. Ariba flows run through SAP Integration Suite, managed gateway for spend management and SAP Business Network; SuccessFactors flows run on SAP Integration Suite (BTP Cloud Integration) iFlows.

Positioning notes (July 2026). Next-gen SAP Ariba is GA on SAP BTP since March 2026 with quarterly releases through 2026–27 and a committed ≥60% back-port of agentic capabilities to current-gen; these T-shirts assume current-gen Ariba Buying & Invoicing — capture the client's Ariba generation and migration timing as a scoping variable. Joule/AI capabilities (Ariba intake agent and Fieldglass gate-pass time capture GA June 2026; AI-assisted SOW deliverables since Q1 2026) do not reduce integration configuration, mapping, or Fieldglass-Services-specific scope — align Joule positioning with the account CSM/SAE before client use.

Fine print

Assumptions & Exclusions

Not all-inclusive; additional assumptions may be added at contracting. Detailed discovery is required for a binding proposal.

Key general assumptions

  • Customer adopts standard SAP functionality and processes (Fit-to-Standard); changes lengthen duration and increase cost
  • ROM estimates only — detailed discovery required for binding proposals; ROM valid 30 days (PMBOK® ROM range)
  • Project language English; customer owns translations, end-user training and change management
  • Delivery aligned to one time zone; customer provides business & IT SMEs and a Project Manager
  • Two system landscapes (Production + non-Production) available as required
  • WRICEFs estimated at high level, to be validated in detailed scoping; 2 SIT cycles + 1 UAT cycle in Realize
  • Customer owns data migration, starting balances and open transaction loads
  • Integrations adhere to SAP Fieldglass standard APIs; custom integration work out of scope
  • Integrations led by customer/partner — SAP-led integrations require a separate Services SOW; restricted activities (endpoints, Company Configuration, extrinsic fields, mapping spec) remain SAP Fieldglass-performed Clarified 2026
  • Supplier collaboration model: licensee adapts processes to standard system behavior
  • One single go-live; no multi-phase rollouts; all T-shirts assume SAP-delivered resources
  • User provisioning via SAP Cloud Identity Services (IAS/IPS) is the recommended approach for SF-integrated landscapes Added 2026

Excluded — custom scoping required

  • DocuSign integration for worker contracts
  • Currency conversion integration with OANDA
  • Tax guidance
  • Multi-ERP support — supported by the Ariba/Business Network integration (child site system ID routing) but adds material backend-side effort per additional ERP; scope separately Reworded 2026
  • Master data re-design · end-to-end process re-design
  • New integration points and integration re-design
  • As-is business process analysis · data cleansing
  • Training on existing customer configuration
  • Configuration/design in remote third-party systems; coordination of customer's third-party vendors
  • Modifications to standard source code; new functionality, extensions, co-innovation, custom development
  • Customer-specific authorization roles and security concepts
  • Interfaces to third-party/legacy systems not explicitly defined (standard BTP integrations expected; effort estimated separately)
  • Report creation/maintenance beyond the standard offering
